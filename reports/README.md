## Inside an October study

```
<study>/
  findings.md                 generated summary with links
  serving.csv                 one row per timing run: throughput, TTFT, TPOT, validity, evidence path
  components.csv              one row per rank per capture: GPU kernel ms by component
  memory.csv                  one row per live-KV snapshot
  components_unclassified.md  kernels the classifier left in "other"
  data/<key>/                 raw runs per model, with CURATION.json (source and published hashes)
  study/_env/                 node inventory: CPU, NUMA, GPUs, driver, installed packages
  study/_inputs/              request-list hashes and corpus sources (texts are not in Git)
```

To trace a number: find its row in `serving.csv`, read the `evidence` column, and open that run under `data/<key>/` (`bench.json` or `bench.json.gz` for the client's per-request results, `summary.json` for the headline values, `blog_validation.json` for the validity checks).

Read each kind of number for what it is: `serving.csv` is unprofiled elapsed time; `components.csv` is GPU kernel sums from a separate profiler launch, and kernels overlap, so a sum is not a latency; `memory.csv` approximates **live** state as usage gauge × per-rank pool, which is neither the reserved pool nor a request capacity.

## Ledgers

- [provenance.json](provenance.json) lists every retained evidence file with its source and exported SHA-256. [docs/provenance.md](../docs/provenance.md) explains the selection.
- `data/<key>/CURATION.json` is the original per-model curation ledger. It is never edited.
- [glm-53-september/provenance.json](glm-53-september/provenance.json) is the separate ledger of the September GLM archive.
- [environment-lock.txt](environment-lock.txt) is the package lock of the September runtime, used by [install.sh](../install.sh).

## Rules for this folder

- **Raw measurements and their curation ledgers are preserved byte-for-byte.** Do not edit, reformat or re-save a file under `data/`, `study/` or the archive. `.gitattributes` turns off line-ending conversion for everything here.
- `five-model/` and both `findings.md` files are generated. Change [tools/build_blog_results.py](../tools/build_blog_results.py) and rerun it; do not edit them by hand.
- A new measurement gets a **new study folder** with its own identity, plan and controls. It never goes into a completed study.
- Every file here must be registered: hashed in a ledger, generated by the builder, or named as an index in [tools/audit_references.py](../tools/audit_references.py). The audit fails on an unregistered file.
- Weights, caches, credentials, private hosts and full profiler traces stay out of Git.
