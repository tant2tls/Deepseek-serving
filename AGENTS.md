# Five-model blog (`main` branch)

Read [README.md](README.md), [target.md](target.md), [docs/experiments.md](docs/experiments.md), [reproduce/README.md](reproduce/README.md) and [docs/provenance.md](docs/provenance.md) before changing this branch.

- Branch roles (2026-10-10): this publication view is `main` (formerly `blog/five-model-reproduction`). The full archive with every study, frozen ledger and the later-study plan is `all-data` (formerly `main`).
- Layout: `bench/` measures on the GPU node, `tools/` builds and checks on any computer, `reports/` holds results, `reproduce/` holds one run guide per model key, `teach_me/` holds the lessons, `docs/` holds protocol, provenance and model references. Each folder's `README.md` says what belongs there and how to add to it. The root holds only `AGENTS.md`, `README.md`, `target.md`, `index.html` and `install.sh`; the audit rejects anything else, so a new top-level entry must be added to its layout list and to the README map in the same change.
- Purpose, from [target.md](target.md), the single target file: measurements that answer Kan's questions, and a blog useful to everyone who reads it. Keep its answered/unanswered table, its answer map and its claims table current.
- Scope: reproduction, setup and completed measurements for the five checkpoints in [target.md](target.md). A model's checkpoint and revision must agree in `bench/serve.sh`, `bench/run_matrix.py`, `target.md`, `docs/models.md` and `reproduce/<key>.md`. Qwen3.8-Flash-Next means its original BF16 checkpoint; do not add another Qwen deployment.
- Preserve raw measurements and their curation ledgers byte-for-byte. Derived tables are regenerated by `python tools/build_blog_results.py` and the article's data block by `python tools/build_blog_page.py`; never edit them by hand. Run `python tools/audit_references.py` on a clean clone after changes.
- The completed main comparison uses vLLM `554340f3d3259e321be4c07282be7a02a5aeef83`. Earlier DeepSeek/MiMo experiments use `44af287ebe38d6dc4e102948025f5e3e175aefd6`; never mix their numbers as controls. Their reports live beside their evidence: [reports/v41-vs-0731/report.md](reports/v41-vs-0731/report.md) and [reports/mimo-v26/report.md](reports/mimo-v26/report.md). The planned rerun uses the latest build frozen at preparation time, with fresh controls, as specified in [target.md](target.md#five-model-rerun-plan).
- All five use the same core setup, but Qwen and the MiMo control were measured on a second physical node. At the user's request, the article displays all five in each serving metric. Retain the node control and explain in the measurement notes that latency differences can reflect the host; do not present them as a controlled architecture ranking. The planned rerun uses one physical node.
- GLM uses native FP8 weights and `reasoning_effort=low`; other models disable thinking. Preserve native precision and loaded implementation evidence.
- Write for university readers with basic computing knowledge. Explain observations before mechanisms. Distinguish attention core from its projections/indexer, live state from reserved pools, kernel sums from elapsed time, and estimates from hardware measurements.
- No new GPU rentals, measurements, prefix-cache experiments, speculative sweeps or H200 work without explicit authorization. Blog launches have prefix caching and speculation off. The rerun plan's speculative arms are proposals under this same rule. Prefix caching will not be measured (user decision, 2026-10-10): do not add a prefix-cache experiment to the plan. The rerun measures 2,048-token outputs only (same decision date): the completed 256-token study is a reference, not something to measure again, and there is no 8,192-token tier. The rental is one 8×H100 node for 15 hours (same decision date): only [the 15-hour session](target.md#the-15-hour-session) runs. Keep it within 15 hours and close to Kan's questions; if time is short, cut serving points, not the attention, state and FFN diagnostics. The user also requested sessions on a 4×H200 and a 4×B200 server (same decision date): follow [docs/H200_B200_plan.md](docs/H200_B200_plan.md), which adds speculative decoding and keeps one checkpoint on disk at a time. Run it only on a server the user hands over, and never download into or delete from the shared Hugging Face pool. Historical scripts and reports are evidence, not an active queue.
- Keep credentials, private hosts/paths, weights, caches and large profiler traces out of Git. New measurements need a new study identity and fresh controls. Stop owned servers on every exit and verify shutdown.
- Commit and push only when requested. Do not merge this publication selection into the full archive (`all-data`) automatically.
